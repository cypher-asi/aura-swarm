# Staged TEE Rollout

Numbered scripts implementing the Swarm TEE upgrade rollout (R1 dual-mode → R2 migration → R3 cleanup) as discrete, individually verifiable steps. Run them **in order, one at a time**: every script ends with explicit verification of its own step and prints `STEP NN OK — proceed to NN+1` or `STEP NN FAILED: <why>`. All steps are idempotent — re-running after a partial failure is safe.

The pre-TEE-rollout scripts live in [legacy/](legacy/) for reference.

## Prerequisites

- `config.env` (sourced by every script) defines region, cluster, node groups, namespaces, and deploy-operator IAM names.
- `.secrets/` at the repo root: `ANTHROPIC_API_KEY` is required before step 06; `INTERNAL_TOKEN` and `kbs-admin.key` are generated by step 04 if missing. Steps 06/07 additionally need an owner JWT in `SMOKE_TEST_TOKEN` (env or `.secrets/SMOKE_TEST_TOKEN`) for test-agent verification.
- The harness image must be pinned to an immutable `@sha256` digest — build it with `legacy/07-build-images.sh --harness` (writes `.last-harness-image.env`) or set `AURA_HARNESS_IMAGE` explicitly.

### Release refs

Steps that deploy swarm builds accept a git ref via `--ref` or env (defaults shown):

| Stage | Env var | Default |
|---|---|---|
| R1 dual-mode | `SWARM_R1_REF` | `fa93895` |
| R2 migration | `SWARM_R2_REF` | `af9e034` |
| R3 cleanup | `SWARM_R3_REF` | `master` |

Platform images are built from a throwaway git worktree at that ref and tagged with the short commit sha (rebuilds are skipped when the tag already exists in ECR).

## Rollout sequence

| Step | Script | What it does | How you know it worked | Rollback note |
|---|---|---|---|---|
| 00 | `00-preflight.sh` | Read-only: tools, AWS/kubectl auth, cluster reachability, fleet report (pods by runtime class, schema version), zbilling reachability. No mutations. | Every check green; `STEP 00 OK`. | Nothing to roll back. |
| 01 | `01-iam.sh` | Deploy-operator IAM for the SSO org: customer-managed deploy policy attached to the Identity Center **permission set** (`DEPLOY_SSO_PERMISSION_SET`) and re-provisioned. **No cluster service roles** (those stay in terraform). Run with an Identity Center admin session. | Policy exists; permission set references it; deploy role passes `eks:DescribeUpdate` simulation. | Detach the customer-managed policy reference from the permission set and re-provision. |
| 02 | `02-snp-node-group.sh` | Terraform plan/apply for the SNP bare-metal node group. **Aborts before apply** if the plan would REPLACE the EFS filesystem (unencrypted → mandatory encrypted). | SNP nodes Ready, labeled `swarm.io/confidential-node=true`, tainted `NoSchedule`. | `terraform destroy -target` the node group, or scale `CONFIDENTIAL_NODE_*` to 0 and re-run. |
| 02b | `02b-efs-encryption-migration.sh` | Only if 02 aborted: guided unencrypted→encrypted EFS migration (new FS, rsync via temp pod, PVC rebind, terraform state repoint) with explicit pause points. | Final rsync verified (file counts match), terraform plan replacement-free; re-run 02 cleanly. | Old filesystem is kept untouched until you delete it manually. |
| 03 | `03-coco-operator.sh` | CoCo operator (pinned `COCO_OPERATOR_VERSION`), CcRuntime CR, `kata-qemu`/`kata-qemu-snp` RuntimeClasses. | Operator controller ready; RuntimeClass exists; all SNP nodes labeled `katacontainers.io/kata-runtime=true`. | `kubectl delete ccruntime ccruntime` triggers the operator's uninstall daemonsets. |
| 04 | `04-trustee-kbs.sh` | Trustee KBS (built-in AS) deploy, KBS admin keypair (`.secrets/kbs-admin.key` ↔ `kbs-auth-public-key` secret), generates `.secrets/INTERNAL_TOKEN` if missing. | KBS pod ready; service resolves + HTTP listener answers in-cluster. | Delete the kbs deployment; per-agent DEKs live on the persistent `kbs-repository` PVC. |
| 05 | `05-snp-smoke-test.sh` | Throwaway pod on `kata-qemu-snp` boots, attests, fetches a scratch DEK via the in-guest CDH; scratch resource is provisioned via `kbs-client` and deleted afterwards. | Pod succeeds and the fetched value matches the provisioned one — end-to-end attestation proven before any product traffic. | Fully self-cleaning (pod, setter, secret, scratch resource). |
| 06 | `06-deploy-r1.sh` | Build+push+deploy gateway/control/scheduler at the **R1 ref** (dual-mode). | Rollouts complete; `/internal/health` ok; legacy kata-fc pods byte-for-byte untouched (pod set, runtime class, spec hash); one test agent lands on SNP with sealed env and a billing sku, then is destroyed. | Redeploy previous images (`--ref` an older sha). Legacy agents were never touched. |
| 07 | `07-r1-soak-check.sh` | Repeatable soak verification: platform health, fleet read-only checks, vault round-trip, tier change, cron wake→run→hibernate, usage + logs APIs — mutations only on its own test agent. | Printed checklist all PASS. | Read-only against prod agents; nothing to roll back. |
| 08 | `08-efs-backup.sh` | On-demand AWS Backup recovery point of the swarm EFS — **the R2 rollback point** — persisted in `.last-efs-backup.env`. | Backup job `COMPLETED`; recovery point ARN recorded. | This step *is* the rollback provision. |
| 09 | `09-deploy-r2-migrate.sh` | Refuses without the step-08 backup. Deploys the **R2 ref**; gateway runs the v1→v2 store migration + DEK backfill at startup; then sets `MIGRATION_RECREATE_LEGACY_PODS=true` and monitors the rolling recreation with pods-remaining progress. | `schema_version=2` via `/internal/health`; migration/backfill log lines; zero running kata-fc pods. | Restore the step-08 recovery point, redeploy R1 (`06`), unset the ConfigMap gate. |
| 10 | `10-r2-convergence.sh` | Convergence **gate**: schema v2, every record tiered + sealed (billing skus derivable), all pods on `kata-qemu-snp`, zero kata-fc, spot-check of N pods' sealed-state env. Refuses to pass otherwise. | `STEP 10 OK`. Safe to re-run while hibernating stragglers wake/migrate. | Same as step 09. |
| 11 | `11-deploy-r3-cleanup.sh` | Gated on 10. Deploys the **R3 ref**, deletes the `kata-fc` RuntimeClass, terraform-applies the shrunk system pool (with the EFS hazard guard re-checked). | No kata-fc artifacts remain; agent pods Running/Ready; fleet report healthy. | Point of low return: R3 code drops legacy paths. Restore = step-08 recovery point + R2 images. |
| 12 | `12-finalize.sh` | Final fleet health report; EFS backup retention reminder — prompts for deletion only after the retention window (`EFS_BACKUP_RETENTION_DAYS`, default 14), never auto-deletes. | All report lines green; `STEP 12 OK`. | n/a |

## R1 soak guidance

Between steps 06 and 08, soak R1 in production for as long as you need confidence: run `./07-r1-soak-check.sh` **repeatedly** during the window (it is cheap and read-only against prod agents). Use `--keep-agent` once and `--agent-id <id>` on subsequent runs to keep a single designated test agent for the whole soak. Only move on to 08/09 when soak runs pass consistently and the R1 exit criteria hold (new agents attest + seal, legacy agents show zero behavior change, tier billing visible in zbilling).

## Shared assets

- `terraform/` — root module + network/storage/eks/ecr modules (EFS encryption is mandatory in the storage module; that is exactly what the step-02 hazard guard protects against on brownfield clusters).
- `iam/` — deploy-operator IAM policy template (applied by step 01 only).
- `k8s/` — platform manifests, templated at deploy time (images, secrets, EFS id) by the deploy steps; never edited in place.
- `config.env` — environment knobs shared by all steps.
- `_lib.sh` — step framing, terraform/ECR/port-forward helpers reused across scripts.
- `legacy/` — pre-TEE-rollout scripts, kept for reference (including `destroy.sh`, `diagnose.sh`, `fix-pending-pods.sh`, and the image build tooling `07-build-images.sh`).
